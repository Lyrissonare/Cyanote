# Cyanote 介绍

> 一个前后端分离的蓝色博客系统：读起来像 Hexo，写起来像语雀。

**Cyanote** 是一套可以自己跑起来的完整博客系统——后端 Node.js + Express + SQLite，公开站点是一个零构建的原生 JS 单页应用，管理台是另一个独立入口。它不做 SaaS、不依赖外部服务，`npm install` 之后就是一台属于你自己的写作机器。

## 一、两种体验，一套系统

Cyanote 的设计目标写在一句话里：**阅读体验参照 Hexo / Butterfly，写作体验参照语雀**。

于是它被拆成了两个互不打扰的前端：

- **公开站点 `/`**：干净的阅读界面，首页 Hero + 最新文章 + 侧边栏组件（站点统计、分类、加权标签云、归档）；
- **管理台 `/admin`**：语雀式的 Markdown 写作台，隐藏入口，公开页面里连一个链接都找不到。

这条边界不是装饰性的。公开站点的 `js/api.js` 明确只做只读请求，整个公开包里没有令牌逻辑、没有写作入口；反过来，管理台资源一律 `no-cache` 下发，不会因为浏览器缓存而停留在旧版本。

## 二、阅读侧：把细节做够

首页的**最新文章**数量可以在管理台调（1–10，默认 3）。有意思的是第 N+1 篇的处理方式：它没有简单地"截断"，而是渲染成一张**幽灵卡片**——上半篇正常可见，下半篇浸入一层缓慢呼吸的蓝色光晕，光晕中央浮着「✨ 查看全部文章」。它既暗示了"后面还有"，又给了一个出口。

其余细节：

| 能力 | 说明 |
| --- | --- |
| 主题 | 暗色 / 亮色一键切换，默认跟随系统，持久化；首屏前内联脚本设好主题，不会有白闪 |
| 未来视效 | 侧边栏开关，霓虹描边 + 玻璃拟态 + 动态网格背景的先锋皮肤，独立于明暗主题 |
| 光标光照 | 柔和的蓝色光晕跟随鼠标，rAF 缓动插值（系数 0.16），静止后自动停机；触屏设备双重隐藏 |
| 文章详情 | TOC 目录随滚动高亮，点击平滑定位；目录与侧边栏合并为单一粘性列，滚动互不遮挡 |
| 列表侧 | 分页、全文搜索、按分类 / 标签过滤，三者可组合 |

其中一个小细节值得一提：TOC 的点击**刻意不使用锚点跳转**——因为这是 hash 路由的 SPA，改 `location.hash` 会把路由带走跳转到别的页面。所以代码里用 `preventDefault()` + `scrollIntoView({behavior:'smooth'})` 手动滚动，注释也写明了原因。

## 三、写作侧：语雀式的编辑器

管理台有五个视图：**文章管理**（默认）、**写文章**、**分类管理**、**标签管理**、**站点设置**。

编辑器本身支持**编辑 / 双栏 / 预览**三种视图，250ms 防抖实时渲染。工具栏 16 个键分四组：

1. 加粗、斜体、下划线、删除线
2. 标题、引用、无序 / 有序 / 任务列表
3. 行内代码、代码块、链接、图片上传、表格
4. 撤销、重做（自维护历史栈，容量 200）

图片支持**拖拽、粘贴、工具栏选择**三条路径，都汇入同一个上传队列：排队上传、逐个在光标处插入 `![name](url)`，成功一个显示一个。另外还有 `Ctrl/Cmd+S` 保存、1500ms 防抖的本地自动暂存（刷新不丢草稿）、标题自动生成 slug。

内容渲染链路是 `marked`（GFM + breaks）→ `DOMPurify` 净化 → 写入 DOM，代码块交给 Prism 按语言高亮并在左上角显示语言标签。

## 四、后端：小而完整

数据层用 Node 22.5+ 内置的 `node:sqlite`，没有原生编译依赖；文章表用 JSON 列存分类与标签，重命名分类或标签时同步刷新所有引用它的文章。API 是一组朴素的 REST 接口：

```
GET    /api/meta | /api/archive | /api/settings
GET    /api/articles        列表（status/category/tag/q/page/pageSize/order）
GET    /api/articles/:slug  详情（令牌可读草稿）
POST   /api/articles        新建          ⚠️ 需令牌
PUT    /api/articles/:slug  更新          ⚠️ 需令牌
POST   /api/articles/:slug/publish | /unpublish
POST   /api/uploads         图片上传      ⚠️ 需令牌
PUT    /api/categories/:from | /api/tags/:from   重命名 ⚠️ 需令牌
```

**令牌**是这个系统安全模型的核心。写操作只认 `Authorization: Bearer <token>`——不支持 `?token=` 查询串，就是为了避免令牌进入访问日志和浏览器历史。令牌优先取环境变量 `CYANOTE_TOKEN`；没设的话，首次启动会**自动生成一个强随机令牌**写到 `data/admin-token`（0600 权限）。系统里不存在任何公开的默认令牌。

在这之上还叠了几层防护：

- **防爆破**：10 分钟内认证失败 10 次，锁定该 IP 15 分钟
- **限流**：`/api` 每 IP 每 5 分钟 300 次；写操作 120 次 / 5 分钟；令牌校验 30 次 / 5 分钟；上传 30 次 / 10 分钟
- **上传按魔数校验**：不信任客户端上报的 MIME 与文件名，只认文件头字节（PNG / JPEG / GIF / WebP / AVIF），扩展名由嗅探结果决定——所以可以携带脚本的 SVG 永远存不进来
- **阅读数防刷**：同一 IP 对同一文章每小时最多 +1
- **上传目录**响应附带 `nosniff` 与 `Content-Security-Policy: sandbox`

## 五、跑起来

```bash
npm install
npm run seed     # 写入 5 篇演示文章（含 1 篇草稿）
npm start        # http://localhost:3810
```

公开站点在 `http://localhost:3810`，管理台在 `http://localhost:3810/admin/`（本地首次启动会把自动生成的令牌打印在控制台）。

项目自带一套 Puppeteer 端到端回归：`npm run e2e`，自动探测本机 Chrome / Edge / Chromium，覆盖首页侧边栏、幽灵卡片与数量配置、光标光照、亮色冲突提示与一键修复、公开站点无写作入口、列表搜索分页、TOC 与高亮、管理台五大视图、工具栏 16 键与撤销重做、图片粘贴上传、保存发布到公开可读的完整链路。实测 **56/56 全部通过**。

## 六、它适合谁

Cyanote 适合这样的人：想要一个**自己完全掌控**的博客，不想被托管平台的编辑器绑架，也不想为了写篇文章去配置一整套前端构建工具链。它有明确的态度——蓝色是它的底色，暗夜蓝光是它的气质，而「未来视效」是它留给你的一点任性。

> 在蓝色的深处，记录思想与代码。
